\begin{abstract}
Since the symbolic era of AI, most knowledge has been encoded in numerous heterogeneous, narrow symbolic systems that describe it in different schemas, which makes it hard to use at scale: knowledge cannot be mined across systems, nor assembled into a universal symbolic backbone.
In this paper we show that the sparse autoencoder (SAE) features of a pretrained LLM form a shared coordinate system in which symbols from different sources can be matched by meaning.
Our approach, \method, encodes a symbol read in its native context into a sparse code with the SAE, re-weights each dimension by its rarity and matches symbols by cosine similarity.
On 12 tasks across 6 kinds of symbolic system, \method outperforms the dense baseline of the same LLM on every task but one and in nearly every model, layer and SAE setting we tried, and is the best training-free method on most tasks.
Beyond accuracy, \method is interpretable where dense baselines are not: every dimension of the sparse code has a human-readable meaning, so each match decomposes into named concepts.
Our work offers a data-driven way to match and align symbols between any symbolic systems, and paves the way to building a universal symbolic backbone tractably.
\end{abstract}

Symbolism and connectionism have long been the two paradigms of AI: connectionism stores knowledge in the weights of neural networks, while symbolism encodes it in symbols under an explicit schema.
Neural networks are trained in a data-driven way, which makes a universal, general knowledge system such as Large Language Models (LLMs) tractable to build given the development of computing hardwares,
whereas symbolic systems are usually constructed by human experts and so difficult to incorporate universal knowledge exhaustively in a single backbone. The dilemma of the Cyc project \citep{lenat1995cyc}, a knowledge infrastructure built by experts over a person-century with about $10^5$ concepts that paused in recent years of information explosion \citep{yang2026generative}, is the standing example.
Most existing symbolic systems, are therefore narrow and domain-specific---knowledge graphs, database schemas, programming languages---each with its own schema and ontology, so they are hard to use jointly. For example, a math problem is a Lean~4 \texttt{theorem} in one proof assistant and a string of \texttt{\$e} hypotheses in Metamath; the same place is named \texttt{TrainStation} and \texttt{RailwayStation} in two different knowledge graphs; and a disease is a name in one ontology and an opaque identifier in another. AI systems now produce mathematics on open research problems, much of it formalized in Lean \citep{openai2026math}, yet formalized mathematics spans several proof assistants, so reusing it requires aligning statements across them.


Putting such heterogeneous systems in correspondence is a classic problem in several communities---ontology matching \citep{euzenat2013ontology}, schema matching \citep{rahm2001survey}, entity alignment \citep{sun2020benchmarking}, cross-language code retrieval \citep{zhu2022xlcost}---but each solves it for its own kind of system, with lexical matchers tuned to its naming conventions or with models trained on aligned pairs. Instead, we use a unified term, \emph{symbolic matching}, to describe all those tasks, and it matters beyond any single community: a general and appropriate approach on symbolic matching allows to construct the universal knowledge infrastructure from numerous existing systems, not from scratch as in Cyc, effectively re-utilizing the human efforts distributed in those systems. Such a universal symbolic backbone is also the foundation of a general-purpose Neuro-Symbolic model at the scale of LLMs, which offers better interpretability than current LLMs \citep{yang2026generative}.

A pretrained LLM supplies such a tool.
Trained on a large general corpus, it reads almost any symbolic system in any format, and contextualize each symbol with its native context via attention mechanism \citep{attention}. 
The hidden states from a LLM are therefore a candidate for symbolic matching. However, they are known to be anisotropic, dominated by directions shared by all inputs \citep{ethayarajh2019contextual, mu2018allbutthetop}, and dense text embeddings tend to favour superficial linguistic similarity over structural correspondence \citep{yang2024analogy}, which brings challenges for matching between systems with different schema or format. 

Sparse autoencoders (SAEs) address those defects gracefully. They project each dense hidden state at a certain layer in a LLM to a linear combination of vectors (called \textit{features}) from a large dictionary matrix, with features being sparsely active and individually interpretable \citep{bricken2023monosemanticity, cunningham2024sparse, templeton2024scaling}. \textit{Since SAEs are trained to construct such a feature dictionary exhaustively over all possible samples in training corpus, it essentially becomes a shared coordinate system for any input token including symbols, } where each feature represents an axis and the weight scalar (called \textit{code}) is the coordinate value. 
Such a coordinate system addresses both defects of the dense state for symbolic merging mentioned above: the common directions that dominate every dense vector become a handful of named, ubiquitous features that can be identified and set aside, and surface form becomes a few lexical features alongside features for meaning, so that two spellings of one concept meet at the concept features.


Upon these merits, we build \method, a general approach for symbolic matching based on SAE feature codes of symbols. The pipeline starts with an LLM reading each symbol in \emph{native context} from its own system, and run the forward inference until the target layer to obtain an intermediate hidden state. The SAE at that layer encodes the hidden states spanning the symbol's tokens into a sparse code vector, which is then weighted by the rarity of each feature with inverse document frequency (IDF). The candidates are ranked by cosine similarity between the weighted codes of query and candidates (Figure~\ref{fig:pipeline}). Such a pipeline is analogous to DNA sequence matching: 
two genomes are judged related not by the long stretches of sequence that every genome shares but by a few informative genes; sequence search accordingly finds relatedness in a few high-scoring local matches, each scored against what chance alone would produce \citep{altschul1990blast}. From this perspective, the sparse features are genes of each symbol that contributes most to matching. 

Thorough empirical experiments show that \method is not merely a plausible storyteller. Across 12 tasks on 6 kinds of system, including formal mathematics in four provers, programs in seven languages, table schemas, knowledge graphs, cross-lingual ontologies and biomedical ontologies, \method beats the dense hidden state of the same model on every task with Gemma-2-9B and on all but one with Llama-3.1-8B, and it is the best training-free method on most tasks.
Ablations show that the rarity weighting, not the sparse basis alone, carries the result: the unweighted code trails dense, so does a random dictionary with the same weighting, and the gain persists across layers, dictionary widths, sparsity levels, model sizes and model families.
Additionally, since the similarity scores are computed named features, every match is interpretable and grounded down to the proportions of the contribution from few features. 

\paragraph{Contributions.} Our main contributions are as follows:

\begin{itemize}[leftmargin=*, nosep, topsep=1pt]
  \item \method, a training-free, general approach for symbolic matching that is interpretable and significantly outperforms baselines (Sections~\ref{sec:method},~\ref{sec:experiments}).
  \item Ablations over layers, SAE dictionary widths, sparsity levels, model sizes and model families to show the robustness of \method, and over rarity weights to show the importance of such a design (Sections~\ref{sec:ablation}, ~\ref{sec:sweeps}).
  \item A feature-level interpretability analysis, including rule-selected case studies, a column-type split locating where a symbolic rule should take over, and merge tests showing that pairwise alignments compose (Sections~\ref{sec:interp} and~\ref{sec:discussion}).
\end{itemize}

\section{\method}
\label{sec:method}

Symbolic matching takes a query symbol $s$ of a source system $A$ and ranks a candidate set $C(s)$ from a target system $B$ so that the counterpart of $s$ comes first.
Let $h_t\in\R^d$ be the residual stream of a causal language model at layer $\ell$ and token position $t$ when it reads a text, and let $E:\R^d\to\R^F_{\ge 0}$ be the encoder of a sparse autoencoder with $F$ features trained on that layer; for a JumpReLU SAE, $E(h)=\mathrm{JumpReLU}(W_{\mathrm{enc}}h+b_{\mathrm{enc}})$ with $\mathrm{JumpReLU}(z)_f=z_f\,\mathbf{1}[z_f>\theta_f]$ and a learned threshold $\theta_f$ per feature \citep{rajamanoharan2024jumping}.
\method represents every symbol by a sparse vector (code) in $\R^F$ with the following pipeline before matching with cosine similarity.

\paragraph{Native contexts.}
Every symbol $s$ comes with pieces of information recorded in its own system, which we call its \emph{views} $v_1(s),\dots,v_m(s)$: the instances of a knowledge-graph class, the axioms an ontology term occurs in, or the sampled cell values of a table column.
Each view is turned into part of input to the LLM, consisting of a \emph{context} $c_j(s)$, followed by the symbol itself (Figure~\ref{fig:pipeline}).
The LLM reads each input in a forward pass to the target layer $\ell$, whose residual-stream states $\{h_t\}$ are handed to the SAE of that layer in the next step.
Table~\ref{tab:benchmarks} lists the views and templates of every dataset.

\paragraph{Sparse code.}
Of each input only the states at the symbol's own token positions $T_j(s)$ are used, as the information from context has been extracted and added to those tokens via self-attention. When the whole text is the symbol---a program, a formal statement, or a table column written as its name and sampled values---$T_j(s)$ is every position.
Each kept token is SAE-encoded first and the codes are averaged afterwards, over tokens and then views:
\begin{equation}
  a(s) \;=\; \frac{1}{m}\sum_{j=1}^{m}\frac{1}{|T_j(s)|}\sum_{t\in T_j(s)} E(h_t)\;\in\R^{F}.
  \label{eq:code}
\end{equation}

where $a(s)$, the \emph{sparse code vector}, has non-negative and mostly zero elements. 

\paragraph{Rarity weighting.}
Over a reference collection $D$ of $N$ symbols, let $\df(f)=|\{u\in D : a_f(u)>0\}|$ be the number of symbols on which feature $f$ fires.
Then each dimension of $a(s)$ is multiplied by the corresponding feature's inverse document frequency,
\begin{equation}
  w(s) = a(s)\odot\idf\in\R^F,\;\; \idf_f=\Big[\log\tfrac{N}{1+\df(f)}\Big]_+ ,
  \label{eq:idf}
\end{equation}
so a feature that fires on every symbol gets weight zero and a feature that fires on few symbols is amplified.

\paragraph{Matching.}
Every symbol is encoded into a sparse code with the pipeline above. Given a query symbol $s$ and a pool of candidate symbols $C(s)$, candidates are ranked by the cosine of the weighted vectors, and by default the top-1 candidate is taken as the predicted matched symbol: 

\begin{equation}
    \hat t(s)=\argmax_{t\in C(s)}\cos\big(w(s),w(t)\big)
\end{equation}

The cosine decomposes exactly over coordinates of all features: $\cos(w(s),w(t))=\sum_f c_f$ with $c_f=w_f(s)\,w_f(t)/(\|w(s)\|\,\|w(t)\|)$, where the contribution of each interpretable feature to the similarity score is available.

\section{Experiments}
\label{sec:experiments}

\subsection{Datasets}
\label{sec:datasets}

Six different kinds of symbolic systems were chosen to test the universal applicability of \method, where every run uses the full test data and the benchmark's own metric code where one exists.
miniF2F \citep{zheng2022minif2f}: from the Lean~4 port \citep{yang2023minif2flean4} we retrieve each problem's statement in another prover among all statements of that prover, with names, proofs, comments and labels stripped so that nothing but the mathematics identifies a problem.
XLCoST \citep{zhu2022xlcost}: the official protocol and evaluator (the pool contains the query's own row, a free first hit); MRR and Precision@6 averaged over the seven query languages.
Valentine \citep{koutras2021valentine}: all 551 joinable and unionable pairs, scored with Valentine's F1 (one-to-one assignment) and MRR.
Common-KG \citep{fallatah2020gold}: 129 NELL--DBpedia reference pairs and 304 YAGO--Wikidata pairs; classes without instances match on their label alone.
MultiFarm \citep{meilicke2012multifarm}: foreign-language terms against the English terms of a \emph{different} conference ontology, so that neither language nor ontology is shared.
Bio-ML \citep{he2022bioml} and OAEI Anatomy \citep{bodenreider2005mice}: biomedical ontologies, NCIT $\to$ DOID on the Bio-ML validation split with its 100-candidate ranking protocol, and mouse $\to$ human anatomy against all 3,298 human classes; about half of their gold pairs have identical labels.
The metric is MRR unless stated; Appendix~\ref{app:benchmarks} gives view formats.
PubChem SMILES / IUPAC / InChI \citep{kim2023pubchem}, notations the model cannot read, are in Appendix~\ref{app:tasks}.

\subsection{Setup and baselines}
\label{sec:baselines}

In the main experiments, we choose two model families: Gemma-2-9B \citep{gemmateam2024gemma2} at $\ell=20$ with the Gemma Scope JumpReLU SAE ($F=131{,}072$, average $L_0$ of 114; \citealp{lieberum2024gemmascope}), and Llama-3.1-8B \citep{grattafiori2024llama3} at $\ell=15$ with the Llama Scope SAE of the same width \citep{he2024llamascope}; other layers, widths, sparsities and model sizes are swept in Section~\ref{sec:sweeps}.
The reference collection $D$ for idf is the candidate pool for miniF2F, XLCoST and Valentine and all symbols of both systems for the ontology and knowledge-graph tasks (Appendix~\ref{app:benchmarks}).

All baselines use exactly the same views and token positions.
\emph{Dense} is the hidden state averaged over symbol tokens and views, similar to the form in Eq.~\ref{eq:code} except for the use SAE.
\emph{\pcone} additionally subtracts the mean of the dense vectors over $D$ and removes their projection onto the first principal direction $u_1$ of $D$, $(I-u_1u_1^\top)(d-\mu)$, the common-direction removal of \citet{mu2018allbutthetop} and \citet{arora2017simple}.
\emph{SAE-unweighted} is the unweighted code $a(s)$, which isolates the sparse basis from the weighting.
\emph{Strings} is the best of word TF-IDF \citep{sparckjones1972statistical}, character 3--5-gram TF-IDF and BM25 \citep{robertson2009probabilistic} over the surface strings of the same views, chosen per task in the strings' favour (Appendix~\ref{app:benchmarks}); TF-IDF over strings separates the SAE features from the weighting.
\emph{Retrievers}: BGE-M3 \citep{chen2024bge} and Qwen3-Embedding-8B \citep{zhang2025qwen3embedding}, embedding models specially trained for retrieval, on the same view texts with the same controls (Appendix~\ref{app:embed}); every similarity is a cosine. They are a reference rather than a like-for-like baseline: a retriever is trained on paired data to emit one similarity, whereas what is under test here is the untrained feature space of a general model.
We compare with no task-specific matcher (such as BERTMap \citep{he2022bertmap} and LogMap \citep{jimenezruiz2011logmap}), as each is built, tuned and usually trained for one kind of system and does not run on the others and cannot meet the requirement of symbolic matching in general.

Table~\ref{tab:main} gives the main results (plotted in Figure~\ref{fig:main}, Appendix~\ref{app:tasks}).
With Gemma-2-9B, \method beats the dense hidden state of the same model on every task, by up to +0.45 MRR (Lean~4 $\to$ Metamath), and is ahead of \pcone and strings everywhere except XLCoST (word TF-IDF marginally ahead) and MultiFarm Chinese (\pcone by 0.006).
A paired bootstrap puts every gain over dense at $p<0.004$ and the gain over \pcone at $p<0.01$ on 14 of 18 comparisons; on MultiFarm and NELL $\to$ DBpedia the two are within noise (Appendix~\ref{app:significance}).
With Llama-3.1-8B the picture holds with smaller margins: \method beats dense on 13 of 14 rows, all but XLCoST MRR (by 0.01), and \pcone on 10, trailing it on NELL $\to$ DBpedia, MultiFarm Russian and Anatomy (Section~\ref{sec:sweeps}).

The magnitude of the gain depends on how similar the two surface notations are.
Isabelle statements resemble Lean~4 and the gain is small (dense 0.912 v.s. \method 0.961, MRR); Metamath and HOL Light read very differently, and dense collapses there to 0.210 and 0.539 respectively while \method keeps an MRR of 0.661 and 0.898.
On MultiFarm, where source and target share neither script nor ontology, strings are near useless (0.23, MRR) and \method gains +0.10 to +0.13 over dense.
At the other extreme, XLCoST programs are translations between coding languages that keep their identifiers, so word TF-IDF is strong (0.468) and the gain over dense shrinks to +0.01, with \method matching the strings within 0.01.

Removing the first principal component from dense hidden states recovers some of the gap on ontology and knowledge-graph terms, whose dense vectors share a large common component, but makes no difference on code, formal statements and tables.
Stronger controls (Appendix~\ref{app:controls})---top-36 PC removal, standardization, whitening, a dense analogue of idf---sharpen the picture.

Even without any training on retrieval objectives, \method outperforms the dedicated multilingual retriever BGE-M3 on 10 of 15 rows (same views, same controls; Appendix~\ref{app:embed}), and against Qwen3-Embedding-8B, a retriever of the same scale as our backbone, it leads on code, YAGO $\to$ Wikidata, MultiFarm Arabic and Bio-ML while trailing on 8 rows, mainly formal mathematics (0.97--0.99 MRR), while it might be attributed to memorization from pretraining data: these datasets have been public under matching names since 2021 \citep{zheng2022minif2f}, in Lean~4 since 2023 \citep{yang2023minif2flean4}, and Qwen3's 36T-token pretraining corpus includes code and STEM data whose contents are not disclosed \citep{yang2025qwen3}.
More importantly, our approach is naturally aligned with the trend of scaling up LLMs and their SAEs: sparse dictionaries now reach tens of millions of features on frontier models \citep{templeton2024scaling, gao2025scaling} and are released for every layer of open models \citep{lieberum2024gemmascope, he2024llamascope}, and \method inherits every such release at no training cost.
The empirical result confirms the benefit of scaling up in symbolic matching tasks: for example, HOL Light MRR rises from 0.87 to 0.94 and Metamath from 0.65 to 0.74 across Gemma-2-2B, 9B and 27B (Section~\ref{sec:sweeps}), whereas a retriever is bounded by its training pairs and must be retrained at each size. \textcolor{red}{(This could be a point to be attacked by reviewers: why using SAE-IDF over dense retrievers; careful discussion needed.)}

\subsection{Layer, width, sparsity, model size and model family}
\label{sec:sweeps}

We sweep the other configurations in \method on Lean~4 $\to$ HOL Light and Metamath (Figure~\ref{fig:ablation}; Appendix~\ref{app:ablation}).
Across all 39 configurations, including different SAE layers, SAE width, sparsity levels and model families and sizes, \method consistently beats both dense and \pcone on both tasks, by +0.18 to +0.55 MRR over dense on HOL Light and +0.08 to +0.58 on Metamath, and beats SAE-unweighted in all 78 runs, by +0.11 to +0.66.
At nearly fixed sparsity, \method rises with every doubling of the dictionary size on HOL Light (0.817 at 16k to 0.935 at 1M) and levels off from 65k on Metamath, while SAE-unweighted drifts down as the dictionary widens.
The same sweeps on Common-KG and MultiFarm (Figure~\ref{fig:sweepkg}) give the same verdict against dense and the unweighted code.
The effect holds from 2B to 27B parameters (Gemma-2-27B: 0.939 and 0.738 vs.\ dense 0.41 and 0.20) and for a second model family: with Llama-3.1-8B and Llama Scope, \method beats dense in all six miniF2F configurations (Table~\ref{tab:llama}).
On Common-KG and MultiFarm, where Llama's layer-15 margin over \pcone is small (Table~\ref{tab:main}), other Llama layers restore the lead (Table~\ref{tab:llamakg}).

\subsection{Feature-level analysis}
\label{sec:interp}

We decomposed up to 300 correct \method matches per task on the ten tasks other than Bio-ML and Anatomy (2,315 in all), and the same pairs under SAE-unweighted.
Each feature is described by metadata from outside our pipeline: Neuronpedia \citep{lin2023neuronpedia} publishes an automatically generated explanation \citep{bills2023language} for 129,642 of the 131,072 features from the SAEs we used.
An LLM sorted the 5,252 explanations that occur into \emph{concept}, \emph{notation}, \emph{surface} (a particular word or script) and \emph{generic} from their text alone; a second, unrelated model agreed on 92\% ($\kappa=0.80$).

Without weighting, every task matches on the same few features.
One feature, ``mathematical or programming notation'' (f106376, active on 99\% of Pile tokens; \citealp{gao2020pile}), is among SAE-unweighted's five largest contributions in 99\% of all correct matches (96--100\% per task, knowledge graphs included) and in none under \method; ``numbers, dates and measurements'' (48\% of the Pile) is there in 81\% and ``open-source license text'' (44\%) in 59\%.
Features active on more than 1\% of the Pile carry 56--91\% of SAE-unweighted's cosine and 0--6\% of \method's (Figure~\ref{fig:interp}, Table~\ref{tab:interp}, Appendix~\ref{app:cases}).
With weighting, two regimes appear.
On knowledge-graph and ontology terms one or two rare concept features usually carry a match (87--94\% of the cosine from features active on $<$0.1\% of the Pile); on MultiFarm a quarter of it is \emph{surface} features firing on both the foreign term and its English counterpart, a translation inside the model's features \citep{templeton2024scaling, brinkmann2025grammatical}.
Formal statements, programs and table columns spread half the cosine over 10--21 features, about half of it \emph{notation} on formal mathematics.

\paragraph{Case studies.}
In Table~\ref{tab:cases}, the Chinese MultiFarm term for \emph{fee} shares no word with ``fee for conference'', and dense ranks this gold 13th.
Without weighting, the largest contribution to their cosine comes from ``mathematical or programming notation'' (53\%), which every pair shares, and the gold falls to rank 40; with rarity weighting, ``fees and payment structures'' contributes 88\% and the gold ranks first.
The HOL Light floor problem shows the same shift: notation leads without weighting (gold at rank 131), ``floor and rounding operations'' with it (rank 1).
Failures are as readable: ``has first name'' loses to ``has name'' because both have the same top feature, ``variable names in programming code'', and the column \texttt{src\_id}, whose only value is 1, meets the gold \texttt{SRI} only at ``positive integers'', which the numeric column \texttt{CONFSC} shares as well.

\section{Discussion}
\label{sec:discussion}

\paragraph{Optimal choice between neural and symbolic representations.}
A neuro-symbolic system must decide when to encode knowledge with its neural part and when to leave to symbolic component \citep{yang2026generative}. Rules are exact where identity is fixed by a definition (equal keys, units, formats), while neural representations suit graded, context-dependent similarity, the ``family resemblance'' of \citet{wittgenstein1953philosophical}.
Splitting the 551 Valentine pairs by the kind of value a column holds (Appendix~\ref{app:valentine}), \method leads dense in every class, with top-1 accuracy of 0.79--0.81 on free-text, categorical and identifier columns but 0.67 on numeric ones, the hardest class for every method.
This indicates that bare numbers, which give the features the least to match, are where rules on ranges, units and value distributions should take over, a hypothesis for future work.

\paragraph{Composition and abstention in symbolic system merging.}
Merging many systems needs pairwise alignments that agree (A to B then B to C equals A to C) and links that group symbols by their true identity.
Over the twelve ordered pairs among the four provers, with mutual top-1 matches as links, \method links almost twice as many statements as dense (coverage 0.64 vs.\ 0.34) at equal or higher consistency (transitivity 0.981 vs.\ 0.963, measured on the triples each method links; purity 0.981 vs.\ 0.979), and its merge comes closest to the true grouping (adjusted Rand index 0.795; dense 0.519, \pcone 0.646; Appendix~\ref{app:ablation}).
A shared space alone does not ensure this: the unweighted code, in the same space, is the least consistent (transitivity 0.902, purity 0.958).
A merge also needs abstention, since under transitive closure one false link fuses two correct clusters.
For answering selectively, the cosine margin between the first two candidates is a usable confidence: at 90\% precision \method answers 24\% of Metamath and 93\% of HOL Light queries, against 1\% and 24\% for dense (Appendix~\ref{app:abstention}).
A doubtful match shows its reason: \texttt{src\_id} (Table~\ref{tab:cases}), among the least confident tenth, shares mainly a generic number feature with gold and winner, where a numeric rule should decide.

\section{Related Work}
\label{sec:related}

\paragraph{Alignment within one kind of system.}
Ontology matching has many systems and a yearly evaluation (OAEI), from logic-based lexical matchers such as LogMap \citep{jimenezruiz2011logmap} to fine-tuned language models \citep{he2022bertmap}, prompted LLMs \citep{hertling2023olala} and LLM agents \citep{qiang2025agentom}; \citet{euzenat2013ontology} survey the field.
Schema matching \citep{rahm2001survey, koutras2021valentine}, embedding-based entity alignment, which learns from seed alignments \citep{sun2020benchmarking}, and cross-language code retrieval with pretrained code models \citep{feng2020codebert, guo2022unixcoder} each have their own methods and benchmarks; none runs unchanged on another kind of system (Section~\ref{sec:baselines}).

\paragraph{Sparse autoencoders.}
SAEs recover sparse, interpretable features from superposed activations \citep{elhage2022toy, bricken2023monosemanticity, cunningham2024sparse, templeton2024scaling, gao2025scaling}, are released as open suites \citep{lieberum2024gemmascope, he2024llamascope}, and give interpretable axes for semantic search when trained on text embeddings \citep{oneill2024disentangling}.
Against doubts about their downstream use \citep{kantamneni2025sparse}, they help here once the code is rarity-weighted.

\paragraph{Neuro-symbolic models.}
Neuro-symbolic systems combine learned representations with explicit symbolic structure \citep{kautz2022third}: differentiable logic and proving (Logic Tensor Networks, \citealp{badreddine2022ltn}; neural theorem provers, \citealp{rocktaschel2017ntp}; NLProlog, \citealp{weber2019nlprolog}; $\partial$ILP, \citealp{evans2018dilp}), probabilistic logic programs over neural predicates (DeepProbLog, \citealp{manhaeve2018deepproblog}), symbolic programs run over neural scene parses (NS-CL, \citealp{mao2019nscl}), and language models paired with symbolic solvers or deduction engines (Logic-LM, \citealp{pan2023logiclm}; AlphaGeometry, \citealp{trinh2024alphageometry}).
Each reasons inside formalisms chosen for its task; none aligns the symbols of independently built systems, the step a universal symbolic backbone needs \citep{yang2026generative} and the one we address.

\section{Conclusion}
\label{sec:conclusion}

\method matches symbols across heterogeneous systems without training: native context, an LLM's sparse autoencoder, rarity weighting and cosine.
On 12 tasks across six kinds of system it beats the same model's dense state on every task with Gemma-2-9B and on all but one with Llama-3.1-8B; both the learned dictionary and the rarity weighting are needed, the gain holds across SAE and model settings, and each match reads as a few rare, named concepts.
An LLM's feature dictionary is thus an interpretable common ground for aligning existing symbolic systems, a step toward a universal symbolic backbone.

\section{Limitations}
\label{sec:limitations}

\emph{What the model can read.} The method is only as general as the base model's reading of each notation and the native context each system offers: it is at chance on SMILES, IUPAC names and InChI, on par with word TF-IDF when two notations share their identifiers (XLCoST), short of context on MultiFarm, Anatomy and label-only knowledge-graph classes, and we dropped context-less symbols such as ICD codes and drug names.
\emph{Protocol.} Every task ranks a given candidate pool in which the query has a counterpart, with one layer per model. A real merging pipeline must also decide how many counterparts a symbol has---none, one or several---under the structural constraints of the merged systems, and be tested by merging many systems with transitivity as the criterion; our margin-based abstention covers only queries that have a counterpart, and such full alignments are left to future work.
\emph{Comparisons.} We compare representations, not dedicated pipelines, and claim no state of the art on any benchmark. Trained retrievers lead on formal mathematics, where memorised aligned statements are possible; the lead over \pcone is within noise on MultiFarm and NELL $\to$ DBpedia and smaller with Llama-3.1-8B; and the idf is computed on the pool being matched (a held-out library costs 0.07 MRR on Metamath; Appendix~\ref{app:controls}).
\emph{Explanations.} Feature names are generated automatically and their types labelled by an LLM; they describe matches but never compute them.

\paragraph{Models and SAEs.}
Gemma-2-9B (42 layers, $d=3{,}584$), Gemma-2-2B (26 layers, $d=2{,}304$) and Gemma-2-27B (46 layers, $d=4{,}608$) are run in bfloat16; the residual stream after block $\ell$ (\texttt{hidden\_states[$\ell$+1]}) is encoded with the Gemma Scope \texttt{gemma-scope-9b-pt-res} (or \texttt{-2b-pt-res}, \texttt{-27b-pt-res}, the latter released for layers 10, 22 and 34) JumpReLU SAEs ($E(h)=\mathrm{JumpReLU}(W_{\mathrm{enc}}h+b_{\mathrm{enc}})$, Section~\ref{sec:method}, with the released per-feature thresholds $\theta_f$).
The main-table SAE is \texttt{layer\_20/width\_131k/average\_l0\_114}, the canonical release, which is the one with Neuronpedia explanations.
Llama-3.1-8B (32 layers, $d=4{,}096$) uses the Llama Scope residual SAEs \texttt{Llama3\_1-8B-Base-L\{8,12,15,20,24\}R-32x} (131k features) and \texttt{L15R-8x} (32k), applied as published, with dataset-wise input scaling and the released JumpReLU threshold.
Texts are truncated to 1,024 tokens (15 of 3,918 Java programs were truncated).

\paragraph{Views.}
Common-KG: up to 16 instances per class sampled with a fixed seed, written \texttt{Instance: <label>. Class: <label>}; a class with no instances gets the single view \texttt{Class: <label>}.
MultiFarm: one view per axiom of the term in its own ontology and language (parents and children, domain and range, properties whose domain or range it is, sub- and super-properties, inverses, disjoint classes), written \texttt{<relation> <other>. Term: <label>}.
Bio-ML and Anatomy: definitions, parents and part-of relations in the same form.
Valentine: \texttt{<table>.<column>: <v1>; <v2>; \dots} with 16 sampled values.
Only the symbol's final occurrence is pooled, and no synonyms are used anywhere.

\paragraph{Reference collections for idf.}
miniF2F and XLCoST: the candidate pool (the target prover's statements; the test file of the query language).
Valentine: the target columns of each table pair.
Common-KG, MultiFarm, Bio-ML, Anatomy: all symbols of both systems.
$\df(f)$ counts symbols, not tokens or views.

\paragraph{String baselines.}
For formal statements and PubChem the ``Strings'' column is the best of word TF-IDF, character 3--5-gram TF-IDF and BM25 over the statements: BM25 on Isabelle (0.825; word TF-IDF 0.772), word TF-IDF on Metamath (0.615; BM25 0.187) and character $n$-grams on HOL Light (0.741; word TF-IDF 0.669).
For XLCoST the official evaluator scores the word TF-IDF ranking.
For ontology and knowledge-graph terms it is the better of character 3--5-gram TF-IDF over labels and word TF-IDF over the view texts.

\paragraph{Compute.}
One 48\,GB A6000 (or two 24\,GB A5000s with the model split across them) runs Gemma-2-9B plus the 131k SAE encoder ($131{,}072\times 3{,}584$ in bfloat16, about 0.9\,GB); Llama-3.1-8B ran on one 40\,GB A100 and Gemma-2-27B on two.
Encoding takes minutes for miniF2F, Common-KG and MultiFarm and a few hours for XLCoST and Valentine; scoring and all analyses run on CPU.

\section{Post-hoc controls and analyses}
\label{app:controls}

The experiments in this section were added after the main results, with their decision rules written down before they ran (\texttt{paper/PREREG\_extras\_2026-10-04.md} in the repository).

\paragraph{Stronger dense controls.}
On the stored dense vectors of every main-table run, each fitted on the same reference collection $D$ as the idf: removal of the top 36 principal directions ($\approx d/100$), per-dimension standardisation, ZCA whitening with Ledoit--Wolf shrinkage, and two \emph{dense-idf} variants that mark a symbol's 114 largest standardised coordinates as active, compute an idf over those activity sets, and weight either all coordinates or only the active ones (Table~\ref{tab:controls}).
The pre-registered rule---drop the anisotropy claim if any single control is within noise of \method on at least 8 of 16 rows---was not met: whitening is the strongest control and ties or beats \method only on the two Common-KG pairs, where it reaches 0.989 and 0.964, while it collapses on MultiFarm (0.14--0.17 MRR), falls below dense on XLCoST and leaves Metamath at 0.465 and HOL Light at 0.786.
For Valentine the transforms are fitted on all target columns of all pairs.

\paragraph{A random dictionary of the same width and sparsity.}
To separate the learned features from sparsity plus rarity weighting, we replaced the SAE encoder by a random one of the same width ($F=131{,}072$; i.i.d.\ Gaussian columns, unit norm, no bias) with one global JumpReLU threshold calibrated so that its mean number of active features per token on a fixed sample of symbol tokens equals the real SAE's on the same tokens (122.6 vs.\ 127.8), and ran the whole pipeline---native views, per-token encoding, averaging, idf over the same collection, cosine---unchanged on every main-table row (Table~\ref{tab:random}).
The pre-registered rule: the title stands if \method is significantly ahead of the random dictionary with idf on at least 12 of 16 rows; the contribution is re-described as rarity weighting of sparse codes if the random dictionary is within noise on at least 8.
The first rule holds: \method is significantly ahead of the random dictionary with idf on 16 of 17 bootstrapped comparisons (the exception is XLCoST C\#, a tie), by 0.10--0.55 MRR on formal mathematics and 0.07--0.30 on knowledge-graph and cross-lingual terms, and the random dictionary with idf is below the plain dense state on every row. The biomedical tasks, run the same way after they joined the main table, agree: \method leads the random dictionary with idf by 0.10--0.13 MRR on both Bio-ML splits and on Anatomy ($p<0.001$), and the random dictionary stays below dense there too.
Sparsity plus rarity weighting is therefore not enough; the learned features carry the result, and the weighting is what makes them usable.
The calibration matched the mean number of active features (122.6 vs.\ 127.8) but not its distribution: with one global threshold on anisotropic activations the random code's median is 50 features and 11\% of its features never fire on the calibration sample, whereas the SAE's thresholds are per feature.

\paragraph{idf from a held-out library.}
The idf of the main table is computed over the candidate pool.
Computing it instead from 3,000 theorems sampled from set.mm (for Metamath) and 3,000 library terms from the HOL Light distribution (for HOL Light), rendered as the test statements are and encoded with the same model and SAE, gives MRR 0.588 on Lean~4 $\to$ Metamath (pool idf 0.661; dense 0.210) and 0.906 on $\to$ HOL Light (0.898).
By the pre-registered threshold (a drop of more than 0.05) the Metamath result makes the choice of reference collection a stated limitation; a library idf is nonetheless far above every dense baseline on both tasks.

\paragraph{A random sample of failures.}
Appendix~\ref{app:cases} selects case studies by rule; here five failures per task on the same ten tasks (gold not ranked first by \method) were drawn uniformly at random (seed 0) and decomposed in the same way, into the features the query shares with the gold counterpart and with the wrong top-1 candidate.
Failure rates range from 0.5\% of XLCoST queries and 4\% of NELL $\to$ DBpedia to 46\% on Lean~4 $\to$ Metamath and 34--37\% on MultiFarm; when \method fails, the gold is still within the top five in 57--100\% of cases, and Dense ranks it first in only 2--10\% of our failures on Metamath, HOL Light, MultiFarm Arabic and Valentine, 16--33\% on MultiFarm Chinese and Russian, YAGO and XLCoST, and 45\% and 60\% on Isabelle and NELL $\to$ DBpedia, so most failures are shared by both representations.
The features carrying the wrong matches have the same explanation-type mix as those carrying the gold (about 62\% \emph{concept}, 16\% \emph{notation}, 5\% \emph{generic} on both sides); the single largest contributor across all sampled failures is a \emph{generic} feature (``specific structured information or categories'') on XLCoST.
The 316 distinct features involved are released with their Neuronpedia explanations for a human check of the automatic names.

\section{Statistical significance}
\label{app:significance}

\section{What did not work}
\label{app:tacit}

Generated contexts (Appendix~\ref{app:generated}) and a drug-name task with shared metadata, where the shared text leaked the answer to both sides.
Pooling hidden states before SAE encoding, which drops features that fire on part of a symbol.
A ``universal'' idf computed from Pile densities instead of the matched collection, which was worse on every task (0.190 vs.\ 0.661 MRR on Metamath) because it does not know which features are generic \emph{for these two systems}.
Qwen2.5-7B-Instruct as a context generator (broken fragments and factual errors).
Using synonyms as context, which hands over the other side's label.
Smaller candidate pools (a 59-pair Valentine subset gave the opposite verdict to the full 551 pairs), which is why every reported number is on full data.
